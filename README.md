# Relocate-UserFolders

**重装系统后，把用户目录搬到数据盘。软件无感，配置零改动。**

C 盘只该装系统。但 Desktop、Downloads、Documents 这些目录只会越来越大，几个月就能吃掉几十 G。

Windows 自带的「属性 → 位置」迁移改的是注册表，遇到硬编码 `%USERPROFILE%` 的程序就露馅——文件又悄悄写回 C 盘。这个脚本在搬完之后把原路径变成目录联接，对系统和所有软件来说老路径依然存在、依然可读写，只是内容实际落在数据盘上。

## 特性

- **软件无感** — 老路径继续可用，不用逐个改配置
- **不需要管理员权限** — 用目录联接而非符号链接，普通账户即可
- **默认演练** — 不加 `-Apply` 只打印计划，不碰任何文件
- **可回滚** — `-Undo` 把内容原样搬回
- **可重复执行** — 已是联接的目录自动跳过
- **安全搬迁** — robocopy 搬运，支持长路径、保留时间戳、占用自动重试

## 快速开始

```powershell
# 1. 先演练，看看会做什么
.\Relocate-UserFolders.ps1 -TargetRoot 'D:\'

# 2. 确认无误后执行
.\Relocate-UserFolders.ps1 -TargetRoot 'D:\' -Apply
```

重装系统后建议**在新账户第一次登录时**跑，此时目录还是干净的。

## 参数

| 参数 | 说明 |
| --- | --- |
| `-TargetRoot` | **必填**。目标根目录，每个文件夹落到 `<TargetRoot>\<名称>` |
| `-ProfileRoot` | 要处理的用户目录，默认当前用户。可指定其他路径以迁移别的账户 |
| `-Folders` | 要迁移的目录名，默认 `Desktop, Documents, Downloads, Music, Pictures, Videos` |
| `-Apply` | 真正执行。不加则只演练 |
| `-Undo` | 回滚：删除联接并把内容搬回用户目录 |
| `-AdoptExisting` | 目标位置已有同名目录时，确认可以合并进去。详见下一节 |
| `-SyncShellFolders` | 同时改写注册表，让资源管理器属性页显示真实位置（重新登录后生效） |

## 常用命令

```powershell
# 只迁下载和图片
.\Relocate-UserFolders.ps1 -Folders Downloads,Pictures -Apply

# 回滚，同样先演练
.\Relocate-UserFolders.ps1 -Undo
.\Relocate-UserFolders.ps1 -Undo -Apply
```

## 目标位置已有同名目录怎么办

如果 `<TargetRoot>\Desktop` 已经存在，脚本会先分辨它是哪来的：

- **上次迁移留下的** — 目标根下有个 `.relocate-userfolders.json` 标记文件，记录着本工具迁过哪些目录。命中标记就直接合并，把迁移后新写进 C 盘的文件并进去。
- **认不出来的** — 可能是你自己建的，也可能是从别处拷来的。脚本**中止**并打印该目录现有多少项，等你确认。确认要合并就加 `-AdoptExisting`。

这个区分无法事后推断，所以只能靠标记文件。它由脚本在迁移成功时自动写入，`-Undo` 时自动删除对应条目。

## 它做了什么

对每个目录：

1. 把原目录内容搬到目标位置（robocopy，可合并进已存在的目录；同名文件以原目录为准）
2. 删掉已搬空的原目录
3. 在原位置建立指向目标的目录联接
4. 在目标根写入标记文件

`-Undo` 逆序执行同样的步骤。

## 注意事项

- **目标盘要一直在。** 目录联接不像注册表重定向会回退——数据盘没挂载时这几个路径会整体失效。
- **别删目标根下的 `.relocate-userfolders.json`。** 删了脚本就认不出哪些目录是自己迁的，之后会要求你手工确认。
- **OneDrive 备份中的目录会被跳过。** 先在 OneDrive 设置里关掉对应目录的备份再跑，否则两边会打架。
- **运行前关掉资源管理器和占用这些目录的程序**，文件被锁住会导致中止。
- **别把脚本本身放在被迁移的目录里**（比如桌面）。
- `AppData` 不在支持范围内——搬它会拖慢系统并让部分程序出错。

## 环境要求

Windows 10 / 11，PowerShell 5.1 或更高（系统自带）。无需管理员权限。
